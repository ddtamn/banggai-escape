# 10 — Tooling

The linters, typecheckers, and config files that keep the codebase honest.

---

## Package manager: pnpm workspaces

| Thing | Where | Value |
| --- | --- | --- |
| Package manager | root `package.json` | `pnpm@12.3.4` (pinned via `packageManager`) |
| Node floor | root `package.json` | `engines.node: ">=20"` |
| Workspace packages | `pnpm-workspace.yaml` | `apps/*` |
| Allowed build scripts | `pnpm-workspace.yaml` | `workerd: true`, `esbuild: true` |

pnpm 10+ **blocks dependency post-install scripts by default**. `workerd`
(Wrangler's runtime) and `esbuild` both need theirs, which is why they are listed
explicitly under `allowBuilds`. If `pnpm install` ever prints "Ignored build
scripts", that list is the place to fix it — do not reach for a blanket
`--allow-all`.

A `.npmrc` exists at the repo root for pnpm settings; it is not something you should
need to change for normal work.

### Filtering

Anything app-specific runs through a filter, using the package name:

```sh
pnpm --filter @banggai/web check:watch
pnpm --filter @banggai/web exec wrangler deploy

pnpm --filter admin dev            # note: the admin package is named "admin",
pnpm --filter admin test           # not "@banggai/admin" (yet)
```

The two workspace packages are `apps/web` → **`@banggai/web`** and `apps/admin` →
**`admin`**. The asymmetry is a scaffold leftover; see
[14-admin-app](./14-admin-app.md#scripts) for the rename.

## Biome — lint + format

Biome is the **single** linter and formatter for the workspace. Config lives in
**`biome.json`** at the root; the binary is a root `devDependency`.

| Script | Command | Purpose |
| --- | --- | --- |
| `pnpm lint` | `biome lint` | Lint only |
| `pnpm format` | `biome format --write` | Format and write |
| `pnpm format:check` | `biome format` | Format check, no writes |
| `pnpm check:code` | `biome check` | **Lint + format + import order — the CI gate** |
| `pnpm fix` | `biome check --write` | Apply every safe fix |

### Settings

| Setting | Value |
| --- | --- |
| Indentation | tabs |
| Line width | 100 |
| Quotes | single (JS/TS and CSS) |
| Semicolons | always |
| Lint preset | `recommended` |
| VCS integration | enabled, respects `.gitignore` |

### What is excluded, and why

`biome.json` `files.includes` excludes, in addition to `node_modules` / build dirs:

| Excluded | Reason |
| --- | --- |
| `**/worker-configuration.d.ts` | Generated by Wrangler; reformatting creates churn |
| `**/src/lib/data/media.ts` | Generated image manifest; same reason |
| `**/drizzle/meta` | `drizzle-kit` migration snapshots — generated, never hand-edited |
| `**/.agents`, `**/.vscode` | Third-party / editor-managed |
| `**/skills-lock.json`, `**/pnpm-lock.yaml` | Lockfiles |
| `**/.svelte-kit`, `**/.wrangler`, `**/build`, `**/dist` | Build output |

### The Svelte override

```jsonc
{
	"includes": ["**/*.svelte"],
	"linter": {
		"rules": {
			"correctness": { "noUnusedImports": "off", "noUnusedVariables": "off" }
		}
	}
}
```

Biome's Svelte support only parses the `<script>` block — it cannot see bindings
used in markup. Without this override it reports every prop, handler, and imported
component that markup consumes as unused. Turning the two rules off for `.svelte`
files is the pragmatic fix; **`svelte-check` is the authority for Svelte files.**

### CSS

`css.parser.tailwindDirectives: true` is what lets Biome parse `@theme`, `@apply`,
`@plugin`, and the other Tailwind v4 at-rules instead of erroring. Without it, every
`.svelte`/`.css` file in the project would fail to parse.

### Practical workflow

```sh
pnpm fix          # let Biome sort the mechanical stuff
pnpm check:code   # confirm it is clean
pnpm check        # then the types + a11y gate
```

Biome does **not** replace `svelte-check`. Run both.

## Typechecking: `svelte-check` + TypeScript

| Command | What happens |
| --- | --- |
| `pnpm check` | `svelte-kit sync` (generates `$app/types`, `$types`, etc.) then `svelte-check --tsconfig ./tsconfig.json` |
| `pnpm check:watch` (app-level) | Same, watching for changes |

`apps/web/tsconfig.json`:

```jsonc
{
	"extends": "./.svelte-kit/tsconfig.json",
	"compilerOptions": {
		"rewriteRelativeImportExtensions": true,
		"sourceMap": true,
		"strict": true,
		"skipLibCheck": true,
		"types": ["$app/types", "./worker-configuration.d.ts"]
	}
}
```

Points to note:

- **It extends SvelteKit's generated config**, not a hand-written one. That file
  (`.svelte-kit/tsconfig.json`) sets `paths` for `$lib` and `$app/*`, pulls in
  `./types/**/$types.d.ts`, and defines the `lib`/`module`/`target` defaults. Because
  it is generated, **`svelte-kit sync` must run before typechecking** — which is why
  the `check` script chains sync first. Do not override `include` in this file: the
  generated entries (notably the `$types` declarations) are load-bearing. This is why
  there is no `"include"` here. If you ever see "cannot find module `$app/...`" or
  "`./$types` is not a module", run `pnpm check` (which syncs) or
  `pnpm exec svelte-kit sync` directly.
- **`skipLibCheck: true` is required.** Without it, the Cloudflare runtime types in
  `worker-configuration.d.ts` collide with `lib.dom.d.ts` — TypeScript reports
  hundreds of "definitions of the following identifiers conflict" and
  "Subsequent property declarations must have the same type" errors originating in
  library `.d.ts` files. `skipLibCheck` skips semantic checking of declaration files,
  which is exactly what is needed. `apps/admin` sets it for the same reason. (Do not
  "fix" it by removing `worker-configuration.d.ts` from `types` — then `Env` and
  `App.Platform` stop resolving.)
- **`strict: true`** — no implicit `any`, no unchecked nulls. Write types that
  satisfy it rather than adding `// @ts-ignore`.
- **`types` includes `./worker-configuration.d.ts`** so the global `Env`,
  `Cloudflare.*`, `ExecutionContext`, etc. resolve for `app.d.ts`. This entry is also
  the root of the [wrangler trap](./12-troubleshooting.md#the-wrangler-types--svelte-check-trap).

Expected output for `apps/web` on a clean tree:

```
svelte-check found 0 errors and 0 warnings
```

Because `svelte-check` reports accessibility warnings, "0 warnings" is the standard
to hold (see [09-seo-and-metadata](./09-seo-and-metadata.md#accessibility)).

> **`apps/admin` needs its generated types.** `worker-configuration.d.ts` is listed in
> its `tsconfig.json` `types`, so `pnpm --filter admin check` fails while the file is
> absent; generate it with `pnpm --filter admin gen`, clearing `.svelte-kit/cloudflare`
> first ([wrangler trap](./12-troubleshooting.md#the-wrangler-types--svelte-check-trap)).
> Both that file and `auth.schema.ts` are committed. See
> [14-admin-app](./14-admin-app.md).

### `packages/content-model`

The shared content contracts are a plain TypeScript package with no build step — it
ships `src/` and consumers resolve it through the workspace link:

```jsonc
// packages/content-model/package.json
{ "exports": { ".": "./src/index.ts" } }
```

Its own `tsconfig.json` sets `strict`, `skipLibCheck: true`, `moduleResolution:
"bundler"`, `noEmit`, and `types: []` (it must not depend on any app's ambient types),
and `include: ["src"]`. Verify it with `pnpm --filter content-model check`, which is
**not** part of the root `pnpm check` — root scripts still target `apps/web` only.

Because it is not built, `apps/web`'s Worker bundle is unaffected by the **type-only**
imports from it: `import type { … }` is erased before Vite ever sees it. `apps/admin`
imports the schemas as values and validates with them at runtime.

The root `pnpm check:code` therefore also checks `packages/content-model/src/**` with
Biome, like any other workspace source.

### Admin-only tooling

`apps/admin` adds a server-side toolchain that `apps/web` does not have:

| Tool | Driven by | Purpose |
| --- | --- | --- |
| **Vitest** | `pnpm --filter admin test` | Two projects: browser (Playwright Chromium) and Node. The only test runner in the repo |
| **Playwright** | `@vitest/browser-playwright` | Browser provider for component tests. Chromium must be installed separately |
| **drizzle-kit** | `pnpm --filter admin db:*` | Schema push/generate/migrate and Studio |
| **better-auth CLI** | `pnpm --filter admin auth:schema` | Generates the auth tables into `src/lib/server/db/auth.schema.ts` |
| **shadcn-svelte CLI** | `pnpm dlx shadcn-svelte@latest add <name>` | Adds UI components into `$lib/components/ui` per `components.json` |

These are covered in [14-admin-app](./14-admin-app.md#testing).

## Vite & SvelteKit config

There is **no `svelte.config.js`**. SvelteKit 2.63+ accepts its configuration inline
inside `apps/web/vite.config.ts` — options passed to `sveltekit()` are split into
SvelteKit config and Vite-plugin-Svelte options:

```ts
export default defineConfig({
	plugins: [
		tailwindcss(),
		sveltekit({
			compilerOptions: {
				runes: ({ filename }) =>          // force runes, except node_modules
					filename.split(/[/\\]/).includes('node_modules') ? undefined : true,
			},
			adapter: adapter(),
		}),
	],
});
```

- The plugin order is `tailwindcss()` then `sveltekit()`.
- `adapter()` is `@sveltejs/adapter-cloudflare` with no options — all Cloudflare
  configuration is read from `wrangler.jsonc` at deploy time.
- **No experimental flags are enabled.** `$lib` is built into SvelteKit 2, so there is
  no alias shim; remote functions and async components are off (and unused).
- `apps/admin` uses the identical shape and the same `sveltekit()`-inline approach.

`apps/web/package.json` also declares `#lib` subpath imports
(`{ "imports": { "#lib": "./src/lib/index.js", "#lib/*": "./src/lib/*" } }`).
They resolve to the same tree as `$lib` but **nothing uses them** — the codebase
imports through `$lib/...` throughout. They can be removed.

## Wrangler and generated types

Each app has its own `wrangler.jsonc` (Worker name, compatibility date and flags, the
`main` entry, the `ASSETS` binding, and dev URLs) — covered in
[11-deployment](./11-deployment.md). They build **two separate Workers**: `banggai-escape`
and `admin`.

`wrangler types` regenerates `apps/web/worker-configuration.d.ts`. It is exposed as
`pnpm gen` and is **deliberately not part of `pnpm check` or `pnpm build`.**

> **Read [12-troubleshooting](./12-troubleshooting.md#the-wrangler-types--svelte-check-trap)
> before running `pnpm gen`.** The output has two shapes depending on whether the
> adapter build output exists, and the wrong one breaks `svelte-check`. The safe
> procedure is:
>
> ```sh
> rm -rf apps/web/.svelte-kit/cloudflare apps/web/.svelte-kit/cloudflare-tmp
> pnpm gen
> ```

## Editor

`.vscode/extensions.json` recommends `svelte.svelte-vscode` and
`bradlc.vscode-tailwindcss`. `.vscode/settings.json` maps `*.css` to the `tailwindcss`
language for completion inside `layout.css`.

Let **Biome** own formatting — run `pnpm fix` rather than relying on an editor's
format-on-save, so output matches `pnpm check:code`.

## Agent / MCP tooling

The repo tracks two agent-related files:

- **`.agents/mcp.json`** — declares a `stitch` MCP server (`npx @_davideast/stitch-mcp proxy`).
- **`skills-lock.json`** — pins the versions (by source repo, path, and content hash)
  of installed agent skills, mostly from `google-labs-code/stitch-skills`
  (`design-md`, `taste-design`, `site-md`, and others).

`.agents/` is excluded from Biome. These files are used by AI coding agents working
on the design system; you do not need them to build or run the site.

## What there is *not*

- **No tests in `apps/web`.** Verification there is types + lint + build + manual
  smoke ([01-getting-started](./01-getting-started.md#the-verification-loop)). Only
  `apps/admin` has a test runner.
- **No CI configuration** is committed (no `.github/workflows`). `pnpm check:code`
  and `pnpm check` are the intended CI steps when it is added — though note they
  currently fail on the unformatted admin scaffold (see
  [12-troubleshooting](./12-troubleshooting.md#biome-fails-on-the-admin-scaffold)).
- **No commit hooks** (no Husky/lint-staged). Run the checks yourself.
- **No pre-commit type gate** — which is why `pnpm check` is in the contributing
  checklist.
- **No root scripts for the admin app.** The root `package.json` delegates only to
  `@banggai/web`; admin commands are run with `pnpm --filter admin …`.
